# 复盘：架构决策记录（ADR-lite）

> 每条 = 决策 → 为什么 → 代价。也是②默写重写的提纲：能对每条讲出"为什么"才算过关。
> 版本脉络：v0.1 基础 → v0.2 混合检索 → v0.3 多轮改写 → v0.4 Web → v0.5 评估 → 进阶（流式/落盘/实验）。

## 一、检索

**1. 双通道混合，而不是单通道。**
向量做同义桥接（"开不了机"≈"无法开机"），BM25 做精确词命中（型号、编号、专有名词）。
代价：两套索引 + 融合复杂度。单向量在术语题上召回不稳，单 BM25 在改述题上全瞎。

**2. RRF 排名融合，不做分数归一化。**
cosine ∈ [0,1]，BM25 可到几十，量纲不可比；归一化随查询词数漂移，脆。
RRF 只认排名（Σ 1/(k+rank)），量纲免疫。代价：丢掉"领先多少"的分数粒度。

**3. k=60 直接用社区值，不调。**
k 是头部钝化参数；粗排的任务是"别漏"（选出 top8 候选池），排序权威在精排——
钝化不伤召回，所以不花预算调它。

**4. 两阶段漏斗：粗排选池、精排定序、降级回纯向量。**
RRF 定谁能进 top8，rerank 模型定最终次序；rerank 挂掉退纯向量序（cosine 量纲与
旧阈值校准兼容，拒答闸不断）。

**5. BM25 不持久化，每次启动从 Chroma 重建。**
单一数据源（chroma 是唯一真相），永不漂移。代价：启动几秒 CPU。
前提：语料小；十万块以上才值得落盘倒排索引。

**6. 零依赖分词器：CJK 双字 bigram + ASCII 整词。**
一个正则全搞定，拒装 jieba（本机 pip 有卡死前科）。中文 bigram 是搜索引擎界的
老办法，召回稳、免词典。

**7. invalidate_bm25() 是常驻服务时代的专属钩子。**
CLI 每次新进程无此问题；Web 常驻后入库必须调它，否则 BM25 通道永远看不到新文档。

## 二、生成与多轮

**8. 拒答双闸：检索阈值（硬闸）+ 系统提示词（软闸）。**
分数闸挡"检索都不相关"的；提示词闸挡"检索相关但资料不含答案"的（苹果题）。
两层缺一不可——阈值管不了语义缺口，提示词管不了分数。

**9. 改写器契约：首轮直通、窗口 6 轮、温度 0、三铁律、异常回原句。**
首轮直通省一次调用；降级契约让改写器**永不致命**——挂了最多样坏一点，不炸管线。

**10. 回答强制 [1][2] 引用锚定出处。**
引用是 RAG 可核查性的底线，也是评估（忠实度 judge）的对照物。

## 三、评估

**11. 免费指标先行，judge 只在 --full。**
hit/MRR/拒答零 LLM 成本，迭代检索层时只跑免费档；动生成层才花钱请 judge。

**12. judge 设计：量表锚点 + 温度 0 + JSON 解析 + 分数校验（bool 不是合法 int）。**
解析失败/分数越界 → None 计数，绝不带崩批跑。

**13. 忠实度公理：拒答不含事实陈述 → 恒 5 分。**
教训现场：拒答题在无特例的量表上"掷硬币"（同输入批跑 1 分、单跑 5 分）——
量规必须钉死边缘案例，不能留给模型即兴发挥。拒答对错归 should_refuse 金标管，
一个指标只回答一个问题。

**14. 阈值用安全窗口校准，不拍脑袋。**
实验：合法问题最低分 0.740，对抗题最高 0.366 → 窗口 (0.37, 0.74) → 取中 0.5。
预测先行（跑之前写下预期），事后解释不算数。

## 四、服务

**15. 裸 ASGI + uvicorn，不装 FastAPI。**
fastapi 不在 chromadb 1.x 依赖树里，装它要赌本机 pip；uvicorn 现成，ASGI 本体
只是一个协程。5 个路由手写 60 行 < 引一次依赖风险。

**16. 流式三件套：meta 先行、executor+next+哨兵、error 帧降级。**
引用清单先于正文到达（渐进披露）；同步生成器用 run_in_executor(None, next, gen, 哨兵)
逐段搬运——哨兵默认值避免 StopIteration 跨线程抛出（PEP 479）；头已发出改不了 500，
降级为 error 帧。

**17. 会话落盘走最小版，安全债显性化。**
sid 清洗（路径穿越防御）在 docstring 里记为明债：对外暴露前必还。
欠账不藏着，是工程纪律不是羞耻。

## 五、Agentic（v0.6）

**18. RRF 通道权重是死旋钮（负结果也是结果）。**
14 块语料 + rerank 掌排序权 + 候选池无竞争 → 权重 0.5~5.0 十倍跨度零效果，
池透视证实 top-8 集合恒定。旋钮醒来的三个条件：大语料 / 候选名额有竞争 / 降级改用融合序。

**19. 语料决定上限，单发管线吃掉全部桥接题。**
精心设计的跨文档事实链，单发 top5 + 强 LLM 全部答对——共置语料造不出真顺序依赖。
承认天花板不是认输，是把实验做完整的必经一站。

**20. 合成语料用生成器不用手写。**
种子固定可复现；答案键（scale_truth.json）与检索库分离——出题人看得见，系统看不见。

**21. 负锚反转：显式否定标签是肯定查询的最佳词汇匹配。**
"支持 NFC 的产品"检索回的全是写着"NFC：不支持"的块，生成层据此答出 180° 反的"0 款"。
检索通道不懂否定；此题的治法不是调参，是换工具（见 22）。

**22. 浏览优先于搜索：构造性完美召回。**
"读完整个货架"的聚合题，按文件整取（get_by_source）一步到位——排序通道
（向量/BM25/rerank 都是）天生与"全都要"作对。Agentic 的本质是选对工具，不是堆循环。

**23. 聚合题是移动靶（前提腐烂）。**
语料从 14→25→121 块，三轮各杀死一批"唯一/最X"类题目（q20/q22 死两次，q18/q23 死一次）。
评估集的聚合题要么锚定实体要么定期重验——语料更新不是免费的。

**24. 闸门问题要问对：充分性框架胜过实体框架。**
"主体一致吗"放过了同族污染（音箱 vs 影音设备）；"片段能否直接回答"一把过。
实体错配是充分性失败的子集——把子集问题问成超集，judge 才有对的答案可给。

**25. 子串陷阱：先判否定词。**
"不一致"包含"一致"，"不能"包含"能"——中文 in 判断的顺序就是正确性。
写 `if "一致" in reply` 之前，先写 `if "不一致" in reply`。

## 方法论（贯穿全部版本的元决策）

- **数据驱动**：改参数 → 预测 → 跑评估 → 对答案；"感觉变好了"不算证据。
- **降级契约**：每个外部依赖（LLM/rerank/改写器）都有失败路径，管线永不致命。
- **单一数据源**：能从唯一真相推导的，不做第二份持久化。
- **零依赖偏执**：新依赖先问"手写成本 vs pip 风险"，本项目至今零新增依赖。
